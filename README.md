# FireSign 運用マニュアル

**バージョン:** 2.3
**更新日:** 2026-07-09
**対象:** FireSign 管理者・運用スタッフ

---

## システム構成

```
管理画面 (firesign_admin.html)
    ↓ Googleログイン後、config.json をワンクリックでDriveへ直接保存
      （未ログイン時は従来通りダウンロード→手動アップロードも可能）
Google Drive (firesign フォルダ)
    ↑ config.json ＋ 画像・動画ファイルを読み込む（20秒ごと）
プレーヤー (index.html) ← FireTV Silk ブラウザで開く
```

v2.0 でマルチゾーンレイアウトに対応。画面を最大4分割し、ゾーンごとに独立したコンテンツを再生できます。v2.2 からは画像・動画とも **Google Drive 1本で管理**します（YouTubeは使いません）。v2.3 では管理画面にGoogleログイン機能を追加し、レイアウト変更などをワンクリックでDriveへ反映できるようになりました。また、プレーヤー側の自動再読み込み間隔を60秒→20秒に短縮し、複数台のFireTVへの反映も `deploy.sh reload` コマンドで一括リロードできます。

## 画面レイアウト（7パターン）

管理画面の「画面レイアウト」で選択します。レイアウトごとにゾーン（表示領域）が決まっています。

| レイアウトID | 内容 | ゾーンID |
|---|---|---|
| `full` | 全画面 | main |
| `main-bottom` | メイン(上80%) + 下帯(20%) | main, bottom |
| `main-top` | 上帯(20%) + メイン(下80%) | top, main |
| `split-lr` | 左右2分割 | left, right |
| `split-tb` | 上下2分割 | top, bottom |
| `main-sidebar` | メイン(左75%) + サイドバー(右25%) | main, sidebar |
| `grid-4` | 4分割 | grid1(左上), grid2(右上), grid3(左下), grid4(右下) |

テロップは画面全体にオーバーレイ表示され、レイアウトに関係なく常に画面の上下いずれかに表示されます。

## 日常操作：テロップ・コンテンツを変更する

### 手順

**① 管理画面を開く**

ブラウザで以下を開く：
```
https://take4-minami.github.io/firesign/firesign_admin.html
```

**② 現在の設定を読み込む**

右上の「☁ Driveから読込」ボタンをクリック
→ Google Drive の現在の config.json が画面に反映される

**③ 内容を編集する**

- **画面レイアウト**：使いたいレイアウトパターンをクリックして選択
- **テロップ文章**：テキストエリアを直接書き換える
- **テロップON/OFF**：トグルボタンで切り替え
- **スクロール速度**：数値を変更（大きいほど速い）
- **画像の表示秒数**：各ゾーンごとに設定可能（動画はファイルの長さ分そのまま再生されます）
- 画像・動画そのものの追加/削除/並び替えは、この管理画面では行いません。Google Driveのフォルダにファイルを置く・消す・ファイル名を変えるだけで反映されます（下記「コンテンツの表示」を参照）

**④ 保存する（2通りの方法）**

**方法A：Googleログイン済みの場合（推奨・ワンクリック）**

1. 画面右上に「Googleでログイン」ボタンが表示されていればクリックし、管理者のGoogleアカウントでログイン（初回のみ。詳しい設定手順は下記「Drive直接アップロード機能のセットアップ」参照）
2. ログイン後、保存ボタンが「☁ Driveに保存」に変わるのでクリック
3. これだけで config.json が Google Drive に直接反映されます（ダウンロード・手動アップロード不要）

**方法B：未ログインの場合（従来通り）**

1. 「↓ config.json を保存」／「ローカルにも保存」ボタンをクリック → `config.json` がダウンロードフォルダに保存される
2. Google Drive を開く：https://drive.google.com
3. 「マイドライブ」→「firesign」フォルダを開く
4. ダウンロードした `config.json` をフォルダにドラッグ＆ドロップ
5. 「既存のファイルを置き換えますか？」→「置き換える」をクリック

**⑤ プレーヤーへの反映を確認**

- プレーヤーは **20秒ごと** に自動で設定を再読み込みする（config.json だけでなく画像フォルダの中身も再スキャンする）
- すぐに反映させたい場合はプレーヤーのページを再読み込みする（FireTV: ホームボタン→Silkブラウザを再起動）か、複数台をまとめてリロードしたい場合は開発PCから `bash deploy.sh reload` を実行する（下記「複数台運用」参照）

## コンテンツ（画像・動画）をGoogle Driveから表示する

画像・動画は両方とも、Google Drive の `firesign` フォルダの中に作る **`content` フォルダ配下の、ゾーンIDごとのサブフォルダ** にアップロードします。フォルダ名でどのゾーンに表示されるかが決まり、フォルダ内のファイル名のアルファベット順に自動で再生されます（v2.2〜。画像も動画も同じ場所・同じ仕組みです。旧バージョンの「YouTube限定公開」「images/ファイル名prefix」方式は廃止しました）。

### 手順

**① content フォルダの中に、ゾーンIDと同じ名前のフォルダを作る**

Google Drive の `firesign` フォルダの中に `content` フォルダを作り、その中に使うゾーンID分のフォルダを作ります。

```
firesign/
└── content/
    ├── main/
    │   ├── 01_welcome.jpg   ← main ゾーンで1番目に再生（画像）
    │   ├── 02_menu.mp4      ← main ゾーンで2番目に再生（動画）
    │   └── 03_notice.jpg    ← main ゾーンで3番目に再生（画像）
    ├── sidebar/
    │   └── notice.png       ← sidebar ゾーンで再生
    └── grid1/
        └── a.mp4            ← grid1 ゾーンで再生
```

- 画像（jpg/png）と動画（mp4）を同じフォルダに混在させてOKです。ファイル名順にそのまま再生されます
- ゾーンIDは大文字小文字を区別しません
- `content` フォルダの中に、そのゾーンIDのフォルダが無い（または中身が空の）場合はコンテンツなし扱いになります
- 選択中のレイアウトに存在しないゾーンIDのフォルダは無視されます（例: `full` レイアウトなら `content/main/` のみ有効）
- ゾーンIDフォルダ名の一覧は、管理画面の各ゾーンの説明文にも表示されています
- 動画は音声なし（ミュート）で自動再生され、最後まで再生し終わると次のコンテンツに進みます

**② ファイルを「リンクを知っている全員」に共有**

1. ファイルを右クリック →「共有」
2. 「一般的なアクセス」を「リンクを知っている全員」に変更
3. 「完了」をクリック

（フォルダ全体を最初から共有設定しておけば、以後アップロードするファイルは個別設定不要です）

### ⚠ Google Driveの容量について

Googleアカウント無料枠は合計 **15GB**（Gmail・写真など他の用途と共有）です。動画をDriveで管理する都合上、動画ファイルが増えると容量を圧迫します。

- 動画は極力圧縮・低ビットレートで書き出す（サイネージ用の小さい画面なのでフルHD高画質は基本的に不要です）
- 15GBで足りなくなった場合は、**Google One のストレージプラン（月額課金）にアップグレードする**運用とします。管理者アカウントでのプラン変更が必要です
- 使わなくなった動画・画像はDriveから削除して容量を空けてください

### ⚠ FireTV Stick での動画再生について

FireTV Stick（特に無印・Liteモデル）はハードウェアの動画デコーダが非力です。複数のゾーンで同時に動画を再生すると、映像が乱れたり、ブラウザが重くなる可能性があります。

- 可能な限り、動画は1画面につき同時に1ゾーンまでに留めることを推奨します
- 複数ゾーンに動画を配置する場合は、実機（実際に使うFireTV Stickの機種）で必ず動作確認してください
- 動作が重い場合は、動画を配置するゾーンを減らす、またはレイアウトを `full` や `split-lr` など少ないゾーン数に変更してください

## 複数台運用（Kioskアプリ配布・一括リロード）

FireSignは何台のFireTVでも**まったく同じレイアウト・コンテンツ**をミラー表示する運用を前提としています。台ごとに表示内容を変える機能はありません。

### 新しいFireTVにKioskアプリを追加する

開発PC（`FireSignLauncher` フォルダがある端末）で作業します。

1. `deploy.sh` を開き、`DEVICES` の配列に追加するFireTVのIPアドレスを1行追記する
   ```
   DEVICES=(
     "192.168.0.25"
     "192.168.0.26"   ← 追加
   )
   ```
2. 追加するFireTV側で「設定」→「マイ Fire TV」→「開発者オプション」→「ADBデバッグ」をON
3. `bash deploy.sh` を実行 → 配列内の全台にAPKがインストール・起動される（新しい端末だけでなく既存の端末にも上書きインストールされるが問題ない）
4. 初回接続時はFireTVの画面に「USBデバッグを許可しますか」ダイアログが出るので許可する

### 全台の表示を一斉にリロードする

レイアウトやテロップを変更したあと、20秒の自動反映を待たずにすぐ全台に反映させたい場合：

```
bash deploy.sh reload
```

APKの再インストールは行わず、起動中のFireSignアプリを再起動するだけなので数秒で終わります。台数が増えても同じコマンド1つで全台に指示を出せます。

## FireTV Stick の初期設定（新しいTVに追加する場合）

1. FireTV Stick をテレビのHDMIに接続、電源を入れる
2. Amazonアカウントでログイン
3. ホーム画面で「アプリ」→「ブラウザ」→「Silk ブラウザ」をインストール
4. Silk ブラウザを起動
5. アドレスバーに以下を入力：
   ```
   take4-minami.github.io/firesign/
   ```
6. 画面をクリックするとフルスクリーンになる
7. フルスクリーンのまま放置するとサイネージとして動作する

### ⚠ 常時稼働させる場合は必ずスリープ・スクリーンセーバーを解除すること

サイネージ用途では画面が自動で暗くなったりスリープしないよう、以下を必ず設定してください。

1. FireTV ホーム画面 →「設定」→「ディスプレイとサウンド」→「スクリーンセーバー」→「開始までの時間」を「なし」に設定
2. 「設定」→「ディスプレイとサウンド」→「スリープ状態にするまでの時間」を「なし」に設定
3. これを設定しないと、一定時間操作がないと画面が暗転・スクリーンセーバー表示になりサイネージが止まります
4. Silk ブラウザ側の省電力設定がある場合も無効化してください

## PC（ブラウザ）で動作確認する場合

`index.html` / `firesign_admin.html` はどちらも静的ファイルで、特別なインストール作業は不要です。GitHub Pages のURL（https://take4-minami.github.io/firesign/ ）をどのPC・どのブラウザ（Chrome, Edge, Safariなど）で開いても同じように動作します。職場PC・自宅PCなど環境を問わず、同じURLにアクセスするだけでテストできます。ローカルにファイルを置いて `file://` で開く場合、ブラウザによってはCORSの制限でDrive APIの呼び出しがブロックされることがあるため、基本は GitHub Pages 経由でのアクセスを推奨します。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 画面が真っ黒のまま | ネットワーク未接続 | FireTVのWi-Fi設定を確認 |
| テロップが古いまま | Drive同期待ち | 20秒待つか、ブラウザを再読み込み、または `bash deploy.sh reload` を実行 |
| 管理画面に「Googleでログイン」ボタンが反応しない/エラーになる | OAuthクライアントIDが未設定 or 設定ミス | 下記「Drive直接アップロード機能のセットアップ」を確認 |
| 「画像の読み込みに失敗」 | URLが間違っている、共有設定がされていない | Driveのファイル共有設定を確認 |
| 管理画面でDrive読込失敗 | APIキーの制限 | Google Cloud ConsoleでAPIキーを確認 |
| 特定ゾーンにコンテンツが出ない | `content/ゾーンID/` フォルダが無い、または名前が間違っている | Driveの `content` フォルダ内のサブフォルダ名がゾーンIDと一致しているか確認 |
| 動画が重い・フリーズする | 複数ゾーンで同時に動画再生 | 動画ゾーン数を減らす、レイアウトを変更する、動画を圧縮する |
| Driveの容量不足で保存できない | 無料枠15GBを超えている | 不要ファイルを削除する、Google Oneでプランをアップグレードする |
| 一定時間で画面が暗くなる | FireTVのスリープ/スクリーンセーバー設定 | 上記「スリープ解除設定」を実施 |

## config.json の構造（v2.2）

```json
{
  "layout": "split-lr",
  "screenIndex": 0,
  "telop": {
    "enabled": true,
    "text": "テロップ文章",
    "speed": 80,
    "position": "bottom",
    "fontSize": 26,
    "bgColor": "rgba(0,0,0,0.75)",
    "textColor": "#ffffff"
  },
  "zones": {
    "left": {
      "imageDuration": 5
    },
    "right": {
      "imageDuration": 5
    }
  },
  "loop": true,
  "errorRetry": 10
}
```

各ゾーンの設定は `imageDuration`（画像の表示秒数）のみです。画像・動画のファイル自体はconfig.jsonには含まれず、すべてDriveの `content/ゾーンID/` フォルダのスキャン結果からその都度組み立てられます。v1.0の `playlist` 配列、v2.0〜2.1のYouTube URL登録・ファイル名prefix方式は、いずれも廃止されました。

## Drive直接アップロード機能のセットアップ（初回のみ・管理者作業）

管理画面から「Googleでログイン」してconfig.jsonをワンクリックでDriveに保存できるようにするには、Google Cloud Console で**OAuthクライアントID**を1つ作成し、`firesign_admin.html` 内に貼り付ける必要があります。この作業は最初に1回だけ行えばOKです（対応済みなら、このセクションは読み飛ばして構いません）。

### 手順

**① Google Cloud Console を開く**

https://console.cloud.google.com/ にアクセスし、FireSignで使っているGoogleアカウント（Driveの `firesign` フォルダを所有しているアカウント）でログインする。

**② プロジェクトを選択（または新規作成）**

すでにDrive APIキー発行時に作成したプロジェクトがあれば、それを選択する。無ければ「プロジェクトを作成」から新規作成する。

**③ Google Drive API を有効化する**

左メニュー「APIとサービス」→「ライブラリ」→ 「Google Drive API」を検索 → 「有効にする」をクリック（すでに有効な場合はスキップ）。

**④ OAuth同意画面を設定する**

1. 「APIとサービス」→「OAuth同意画面」
2. User Type は「外部」を選択（個人アカウントのため）
3. アプリ名（例：FireSign管理画面）、サポートメール、デベロッパー連絡先メールを入力して保存
4. 「テストユーザー」の項目で、ログインに使うGoogleアカウントのメールアドレスを追加する（これをやらないとログイン時にエラーになります）
5. 公開ステータスは「テスト」のままでOK（一般公開の審査は不要）

**⑤ OAuthクライアントIDを作成する**

1. 「APIとサービス」→「認証情報」→「＋認証情報を作成」→「OAuthクライアントID」
2. アプリケーションの種類：「ウェブ アプリケーション」を選択
3. 名前：任意（例：FireSign Admin）
4. 「承認済みのJavaScript生成元」に以下を追加：
   ```
   https://take4-minami.github.io
   ```
5. 「作成」をクリックすると、クライアントID（`〜.apps.googleusercontent.com` の形式の文字列）が発行される

**⑥ クライアントIDを管理画面に設定する**

発行されたクライアントIDをコピーし、`firesign_admin.html` 内の以下の行を書き換える：

```js
const GOOGLE_OAUTH_CLIENT_ID = 'YOUR_OAUTH_CLIENT_ID.apps.googleusercontent.com';
```

↓

```js
const GOOGLE_OAUTH_CLIENT_ID = '（発行された実際のクライアントID）';
```

書き換えたら GitHub にプッシュ（または通常の反映手順で）反映する。

**⑦ 動作確認**

管理画面を開き、右上の「Googleでログイン」をクリック→ ①④で設定したテストユーザーのアカウントでログインできればOK。保存ボタンが「☁ Driveに保存」に変わり、ワンクリックでconfig.jsonがDriveに反映されるようになります。

### 注意点

- クライアントIDは「公開情報」扱いです（ブラウザのJSに直接書かれる想定のもの）。ただし「承認済みのJavaScript生成元」を `https://take4-minami.github.io` に限定しているため、他のサイトからは悪用できません
- テストユーザーとして追加していないGoogleアカウントではログインできません（複数の管理者がいる場合は全員分をテストユーザーに追加してください）
- ログインしなくても、従来通り「ローカルにも保存」→手動アップロードでの運用は引き続き可能です

## Claude「プロジェクト」との使い分けについて

Claude の「プロジェクト」機能に途中まで書きかけのFireSignがある場合、**GitHubリポジトリ（https://github.com/Take4-Minami/firesign ）を唯一の正とする**ことを推奨します。理由：

- Cowork（このセッション）はプロジェクトの中身を直接参照・同期できません
- 複数の場所でファイルを編集すると、どちらが最新か分からなくなり事故のもとになります

運用案：
1. 今回 Cowork で作成した `index.html` / `firesign_admin.html` / `README.md` を GitHub に反映する（コミット・プッシュ、またはGitHub Web UIでアップロード）
2. Claude「プロジェクト」側の書きかけファイルは、GitHub の最新版で上書きするか、参照用に「アーカイブ済み」であることをメモしておく
3. 以後の編集は GitHub 上のファイルを基準にし、Cowork でもプロジェクトでも「まずGitHubから最新を取得してから編集する」運用に統一する
